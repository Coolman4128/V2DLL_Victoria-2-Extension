V2DLL 5.75 "ooshunt" - диагностическая сборка для поиска причины рассинхрона

База: исходники 5.74 + два новых инструмента. Сами патчи симуляции не менялись,
зонды только читают состояние - рассинхрон из-за сборки возникнуть не может.

УСТАНОВКА (на ВСЕХ машинах сессии, файл должен быть одинаковым):
1. Переименовать lua51_5.75_ooshunt.dll -> lua51.dll (рядом с v2game.exe),
   lua51_real.dll должен остаться на месте.
2. В v2dll_settings.ini (свой в папке мода при LOCAL_MOD_CONFIG=1) добавить:
     SP_WINDOW_FROM=1871.12.1      ; начало окна, формат ГГГГ.М.Д
     SP_WINDOW_TO=1872.1.20        ; конец окна
     MONEY_WATCH_TAGS=             ; пока пусто (по умолчанию KUK)
   Окно = примерно месяц вокруг даты стабильного рассинхрона.

ПРОЦЕДУРА:
Шаг 1. Все грузят сейв, играете до рассинхрона. В Logs\v2dll_state.log внутри
  окна каждый день пишутся сырые дампы D (страны/штаты/фабрики + попы).
  Сравнение хоста и клиента: Patches\compare_state_detail.py host.log client.log
  или compare_country_fields.py - увидите ПЕРВЫЙ день, страну и поле расхождения.
Шаг 2. Если расходится казна страны (как в деле KUK): вписать её тег в
  MONEY_WATCH_TAGS на всех машинах, повторить прогон. В Logs\v2dll_watch.log
  попадёт КАЖДАЯ запись в казну этой страны: eip + до 5 адресов возврата +
  новое значение. compare_watch_logs.py покажет первую запись, где хост и клиент
  разошлись - эти адреса = точный код-виновник (VA = RVA + 0x400000, см. Ghidra).
Шаг 3. Прислать/сравнить v2dll_watch.log обеих сторон (и v2dll_rng.log для контроля
  потока Random). Дальше - разбор найденной функции в декомпиле v2_mp_sync_re.

ЗАМЕТКИ:
* Ключи косметические - не входят в ConfigFingerprint, но для чистоты опыта
  держите одинаковые значения на всех машинах.
* D-дампы в окне ~1-2 МБ/день; логи ротируются (.prev, до 6 копий).
* Проверка версии: первая строка Logs\v2dll.log и v2dll_oos.log должна показать
  dll=5.75 у всех игроков.
Артефакты: lua51_5.75_ooshunt.pdb - символы для разбора крэш-дампов этой сборки.

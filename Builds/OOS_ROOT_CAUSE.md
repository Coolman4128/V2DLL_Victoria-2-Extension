# Рассинхрон 1910-04-05 (KUK): причина и лечение

Сессия: обе машины dll=5.75, отпечатки cfg/defs/prod идентичны, файлы установок
идентичны (4942 файла, FNV-суммы равны). Загрузка 1910-03-15, OOS 1910-04-05,
дельта движка ровно -1 (51693 против 51694).

## Цепочка доказательств

1. v2dll_state.log: группы hc (страны) и hs (сбережения штатов) расходятся
   с ПЕРВОГО дня (1910-03-15), фабрики/пулы/попы/рынок совпадают.
2. Z-анализ дня 1: расходится ровно ОДНА страна - индекс 115 = KUK.
3. Сырые D-дампы: на входе первого тика казна KUK: хост 0.00, клиент 52664.71.
4. D S 115: сбережения штата #25: хост 118200.71, клиент 65536.00.
5. Байтовая идентичность: хост S25 = 0xE6DC5B46 = 0x7FFFFFFF + 0x66DC5B47,
   т.е. "клампованное int32-значение + казна клиента" байт-в-байт.
   Сумма "казна + сбережения" у обеих машин одинакова: 0xE6DC5B46.
6. v2dll_rng.log: поток MT19937 идентичен все 22 дня (mtidx/mth равны),
   список людей одинаков (RUS,JAP) - RNG не виноват.
7. INA/FRA/TUR/SCA/GER/CHI расходятся позже - каскад через рынок и ИИ.

## Причина

Сбережения штата #25 KUK в сейве (~118200 фунтов = 0xE6DC5B46 в fixed point
2^15) ПРЕВЫШАЮТ диапазон int32 (65536.00 = 0x80000000). При записи MP-сейва
значение расщепляется: savings = min(S, 0x7FFFFFFF), излишек (52664.71)
выгружается в казну страны. Хост играет с полным int64-значением, клиент
получает расщеплённое - состояния различаются с момента загрузки,
движковая чек-сумма догоняет это только на 22-й день.
Тот же класс бага: дело 5.68 (KUK #25, +93399 у хоста против +65338 у клиентов).

## Лечение (5.76, PATCH_STATE_SAVINGS_CAP)

На входе дневного тика (хук FUN_00682EC0, до симуляции) превышение капа
(STATE_SAVINGS_CAP_POUNDS, по умолчанию 60000) переносится из сбережений
штатов в казну страны одинаково на всех машинах (int64). Проверено на сырых
значениях дела: хост 0xE6DC5B46 -> (60000, 0x71AC5B46);
клиент 0x7FFFFFFF + 0x66DC5B47 -> (60000, 0x71AC5B46). Сошлось байт-в-байт.
Ключ входит в ConfigFingerprint: все игроки обязаны иметь одинаковые значения.

Примечание: money watch в этой сессии не сработал по двум причинам:
MONEY_WATCH_TAGS=1 вместо тега, и потому что перевод происходит при загрузке,
до постановки точек. Для поимки следующего такого бага: MONEY_WATCH_TAGS=KUK.

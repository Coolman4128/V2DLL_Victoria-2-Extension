# R02r — EXE thread import quartet transaction

R02r groups the default-enabled executable `kernel32` imports `CreateThread`, `LoadLibraryA`, `LoadLibraryW` and `GetTickCount` into one bounded installer. It replaces the four independent `HookIat` writes in `InstallEngineStability` and the repeated four-write route in `TryPatchLateModules`. Successful callback targets, original-provider forwarding, compiled defaults and ordering remain the same. The group's failure now stops later stability installers and the late D3D/TBB route; earlier independent timer, select, priority or heap effects may remain. The production startup decision is still hard **WITHHELD**, so no game, candidate, deployment or live EXE mutation occurred.

The focused `ExeThreadIatTransaction` authenticates a PE32 import-by-name quartet at the four pinned aligned IAT RVAs and resolves all four current `kernel32` providers before protection changes. It checks every slot against its provider, publishes all four originals before exposing any hook, acquires protection for all four sites, then uses aligned compare-and-exchange in the existing order. A failure triggers reverse recovery and protection restoration; a foreign slot is never overwritten for recovery. Clean recovery is reported as `RolledBack`, while incomplete recovery becomes terminal `RollbackFailed`/`Poisoned`. Historical known or possible hook exposure keeps the original provider pointers valid even after clean rollback. A no-wait interlocked guard defers concurrent or reentrant retries; installed retries validate the cached hook/provider identities and four live slot values without reparsing PE metadata. The latter relies on the caller's pinned-image and provider-lifetime prerequisites and is not a process-wide four-slot atomicity claim.

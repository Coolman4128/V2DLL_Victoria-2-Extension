## Documented ABI and pinned identity

[CreateThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createthread) takes six WINAPI arguments and returns a thread HANDLE or NULL. [ThreadProc](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/ms686736(v=vs.85)) is DWORD WINAPI(LPVOID); its return becomes the thread exit code. The production typedef, HookCreateThread, PinnedThreadStart and callback pointer types use those x86 shapes. The API may run a runnable child before returning; suspended creation defers start until [ResumeThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-resumethread). Loader initialization serializes actual execution, so this evidence does not invent an engine-safe phase or permit waits inside DllMain.

## Limits and remaining leaves

Normal supported conditions require a valid WINAPI callback/parameter lifetime, expected valid provider, successful process-heap allocation and ordinary completion/resume on the tested x86 host with SSE2/FXSR/DAZ capability. This contract does not support unknown providers, arbitrary callback behavior, forced thread termination, DLL unload while callbacks live or unsupported native objects. Original caller parameter ownership is unchanged; the wrapper frees its own context only. Thread termination before wrapper execution can strand that context. HeapFree failure is unchecked in production; cleanup may affect LastError, whose exact preservation is not promised. Tests must not repair or exercise fatal termination to erase these preexisting limits.

CreateThread documentation recommends _beginthreadex for CRT-using threads and identifies CRT low-memory termination risk. Existing PinFpu calls _controlfp_s; this normal current-build evidence excludes arbitrary CRT allocation/error paths. No CRT API substitution or frozen FPU retuning is made. Callback bodies can subsequently change their own controls; the wrapper only establishes its existing entry controls, not perpetual pinning or complete FP register/status preservation.

_beginthreadex, late TBB/D3D/object phase, select/sleep/timer and other M1 dependencies remain separate leaves. M2 POP/M3 savings object/lifetime/phase and other active installer dispositions/full profile acceptance remain parent S02 work. R02b VIEWS and R02d CrashWatch blocks stay enforced. No mandatory remedy/settings/body/order is changed, no OOS/stabilization investigation starts, and no required army/performance feature is accepted here.

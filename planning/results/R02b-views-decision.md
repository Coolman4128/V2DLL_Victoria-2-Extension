## Enforced production route

`Install()` now calls `InstallOptionalViewsFamily()` once in place of the old four-slot patch loop. The helper performs only an ordinary installation log reporting the optional family unavailable and concrete missing profile reasons. It does not call the pure transaction seam, resolve native GUI objects, publish originals or write a slot. Logging continues to respect the existing log setting; no settings/defaults/aliases or generated configuration are silently changed. Existing internal fake-element preparation is inert without installed callbacks and is not a native object registration.

`Fork/ViewsBoundary` reserves the four4-byte PE32 slot spans. Shared `PatchSlot` rejects any overlapping target or original-output destination before pointer addition, protection changes or output publication. Its exposed mod API delegates to that same helper. `StealToTrampoline` and its API wrapper likewise reject overlap in the source patch span, trampoline destination or original-output destination before validation reads/writes. Unsigned PE32 distances account for negative-index/modulo aliases, unaligned straddles and wraparound. Adjacent nonoverlapping spans remain outside this deny rule. Existing unrelated helper behavior is retained; this change is not general validation or transaction repair for every old installer.

The rule protects these provided mutation routes. Arbitrary native plugin code can use gameBase or independent process APIs/direct memory writes; it is unsupported and is not sandboxed. Other independent built-in installers, object-vtable/IAT/D3D changes and the whole active startup gate remain separate parent S02 work. No candidate may be loaded before that gate passes. The pure `InstallViewsFamily` transaction seam and actual Win32 memory backend remain uncalled by production; their established all-or-rollback/output-withholding contracts are retained.

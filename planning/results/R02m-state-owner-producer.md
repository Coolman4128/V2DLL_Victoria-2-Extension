# R02m — bounded native state-owner producer

R02m found a **supported conditional native producer path** for the previously sampled country/state relationship. In one pinned original-game creation branch, a country pointer read from the current session's country vector is passed to a state-building routine. That routine supplies the **same country's** `+0x1C` TAG word and `+0x20` numeric index to a typed `CState` constructor, which directly stores them at `state+0x58/+0x5C`. It then puts the new state pointer in a list node and links that node into that country's `+0xE44` list, provided the state and node allocations succeed. This closes one producer/list-association edge at specified program points. It does not establish every state object's owner, persisted field values after all helpers, generation/lifetime, safe exclusive phase or a supported fork profile. Parent S02/R02 remain incomplete, all current profiles Rejected/WITHHELD, and S03 closed.

The input is the exact pinned PE32 `v2game.exe`, SHA-256 `62D48C204364DD706584777C2E2B3C7AB3C5F1DD0170872554943575D53D6648`, preferred base `0x00400000`. All addresses here are **preferred VAs**, not R02k/l relocated runtime addresses. Root independently checked the final deep lane's **10** complete native byte/disassembly spans against the pinned PE and separately validated the routine inventory's six spans, offsets and vtable/COL evidence. Raw occurrences of `0xE44` or `0x5C` alone were not classified as typed field accesses.

The direct caller at `0x63F047..0x63F06B` reads the current session global `0x012588E8`, walks session `+0xADC` country slots and pushes a slot pointer and zero to call `0x521560`. R02k/l actual-game samples and pinned RTTI identify sampled members of that vector as `CCountry`; the static caller does not prove every future slot valid. In `0x521560`, `0x521683` loads EBX from first stack argument, and the routine uses EBX's `+0x9D8/+0x9DC` province-ID vector with session `+0xACC` province slots. On its creation branch around `0x521766`, it requests `0x290` bytes, pushes byte argument 1, the **address** `EBX+0x1C`, and the new object pointer to `0x4CDC60`. The constructor writes the pinned `CState` vptr at `0x4CDCC3`; at `0x4CDCE5..0x4CDCED` it copies the pair's first two words to new `state+0x58/+0x5C`. The first country word is the TAG record; the second is the numeric country index corroborated by R02l's native consumer and sampled `CCountry` slots.

After constructor return, `0x521794..0x5217E5` requests a `0x10`-byte node and writes DWORDs `[node+0]=that state`, `[node+4]=old country tail`, `[node+8]=0`, plus **byte** `[node+0xC]=0`; it updates that EBX country's tail `+0xE48`, count `+0xE4C`, and either previous node `+8` or empty-list head `+0xE44`. The state pointer and country pointer on this path are the same values used at the preceding constructor call. This matches the **shape** of R02k/l's independently re-resolved actual `CCountry+0xE44 → node+0 → CState` chain; it does not prove those particular saved/loaded objects were made by this branch.

The constructor's byte-1 path also calls `0x9C1390`. Its directly decoded body and the `0x9C1590` helper write state `+8/+0xC/+0x10` and external hash/list structures; neither finite decoded span directly writes `+0x58/+0x5C`. Their transitive/external effects are not fully closed, so the claim is **direct field stores followed by same-object list association**, not a proof that the values remain unchanged at every subsequent point. Allocation-failure branches can continue into count/tail updates with null state/node values; their safety is not established. The successful branch does not prove transfer/reparent, teardown, save generation, complete owner uniqueness, thread/phase or exception/FPU behavior.

An independent command consumer at `0x57CFD0..0x57D05B` resolves a country by command index, walks its `+0xE44` nodes (`node+0` state, `node+8` next), matches state key `+8/+0xC`, then reads state `+0x58/+0x5C`. At `0x57D02D` it indexes the country array with state `+0x5C`; `0x57D033` compares that index to the **newly resolved** country's `+0x20`, rather than directly checking the first list-owning country. It supports native index self-consistency on that command path, not an unconditional safe getter: a missing state can reach a null dereference, which current fork source separately treats as a pre-existing crash fix. Root identified the command RTTI/vtable relation; no actual command object was sampled in R02m.

A second typed path supports the constructor pattern without expanding the main claim. Pinned `CCountry` vtable slot 4 at `0xDFFADC` reaches virtual routine `0x4FBC10`, which sets EBX=ECX and dispatches a concrete case to `0x4FC0A4`. That case passes `&country+0x1C` to `0x4CDC60` and later attempts a similar list append. An intervening state virtual call at `0x4FC0EC` and allocation-failure behavior remain unclosed, so this alternative is corroboration of the field-source pattern, not evidence that the created field values persist to its append or every creation path.

# R02v — pinned d3d9 embedded device-vtable lifetime disposition

The actual original-Lua/HPM device returned in R02u had object address `0x0D4DE080` and writable `MEM_PRIVATE` vtable `0x0D4E0FDC`. Their difference is exactly `0x2F5C`. R02v traces the pinned physical SysWOW64 d3d9.dll instructions that allocate a device, construct a provider-image vtable, copy that table into an embedded field at device+`0x2F5C` before publishing the output device, and later overwrite part of the embedded table on bounded Reset paths. This **explains the observed heap-table layout** without making the current R02t image-backed installer compatible. No game, debugger, native call, candidate DLL, product file or setting was touched in R02v.

## Exact native facts and limits

The pinned provider is the R02u d3d9.dll SHA-256 `FD72E021C128A98A5D688EB9ACC07E3EB1948CA6B630B9FA5F328898E78C7DBC`, preferred image base `0x10000000`. R02u independently normalized the entire captured mapped `.text` to this disk image. All addresses in this ledger's static trace are preferred provider VAs; subtract `0x10000000` for RVAs. They are **not** new live breakpoint observations.

- The sampled heap table's first 20 DWORDs normalize exactly to either provider-image template at RVA `0x1008` or `0x2034`; a third template at `0x2D44` shares selected methods but differs within those 20 words. Both matching templates have slot16 Reset target RVA `0xE06A0` and slot17 Present target RVA `0xE02A0`, as observed live. SDK `IDirect3DDevice9` order identifies IUnknown slots0–2 and Reset/Present slots16/17. Template equality alone does not identify which constructor variant produced the sampled object.
- In the bounded normal `CreateDevice` path, provider method `0x10040050` reaches inner routine `0x1004FC12`, which allocates a device with one of two sizes (`0x3220` or `0x4118`) and calls constructors installing image template A or B. Before storing the device to the caller's output, it reaches device method slot+`0x2AC`. Template A dispatches via `0x10041E20` to `0x1008C080`; template B dispatches directly to `0x1008C080`. At `0x1008C6B1..0x1008C6D1`, this routine checks `[device+0x2F58]==0`, saves the original image-table pointer there, writes `device+0x2F5C` into `[device]`, and copies `0xAF` DWORDs (700 bytes) from the original image table to that embedded location. Both object allocation sizes contain the `0x2F5C..0x3218` copied-table span. This is an exact pinned **producer path before output publication**, conditional on its normal branches. R02u did not capture `[device+0x2F58]` or the entire 175-word live table, so static path correspondence is distinguished from observed execution of every instruction.
- The original-game call used creation flags `0x40`; frozen `HookCreateDevice` would add `D3DCREATE_FPU_PRESERVE` bit `0x2` and pass `0x42`. The bounded native variant test uses bit `0x10`, clear for both values and selecting the `0x4118`/template-A branch. At `0x1008C689`, bit `0x2` jumps directly to the same copy check `0x1008C6B1`, while flags `0x40` run the local FPU-control setup then fall through there. Thus the frozen flag changes that local FPU branch but **does not bypass the embedded-table copy on this bounded path**. The fork path was not executed; other flag mutations or derived classes are not inferred away.
- The observed Release target, provider RVA `0x65AF0`, uses `lock xadd` on a refcount at device+`0x38`. On the bounded zero-ref **and matching current-thread** branch it dispatches through device vtable slot+`0x2B8` (the last of the 175 copied entries) with delete flag one. Static A/B slot targets converge through variant destructor wrappers; those rewrite the vptr to static templates, then their scalar-delete branch computes the aligned allocation base as `device − DWORD[device−4]` and calls imported `LocalFree`. The preceding DWORD is an alignment offset, not itself the base pointer. Other refcounts, wrong-thread branches and derived/foreign paths are not covered. R02u did not read the live heap table's destructor slot; its copied value is a conditional static inference, not an observed call.
- The observed Reset target, provider RVA `0xE06A0`, reaches `0x100E0841`. On bounded negative-status/branch paths ending at `0x100E123D..0x100E1251`, native code copies `0x77` DWORDs (119 entries) from the saved image template `[device+0x2F58]` back into the embedded table at device+`0x2F5C`. This includes slots16/17, so a hook placed in those slots can be overwritten. Other paths bypass this copy; the condition and frequency of driver-specific branches remain unobserved in the original game.

Root's independent review and the private Sol/Luna manifests pin exact bytes, file offsets, complete instruction boundaries and finite control-flow frontiers for these claims. Static reachable paths do not prove that a given branch ran on the one sampled device, that no other code changes its table, that all devices use these two templates, or that Reset/Release execute only on the sampled caller thread.

## Installer strategy decision

| Strategy | Finite disposition | Material remaining condition |
| --- | --- | --- |
| Keep R02t's authenticated image-backed table guard | **Supported fail-closed behavior** for the observed heap table. It rejects before hook publication and preserves the provider's returned HRESULT/object. | Current D3D profile remains unavailable; no candidate launch follows. |
| Permit and patch the embedded heap table with a device-scoped journal | **Blocked under the current implementation.** The table's address is object-relative, Reset can overwrite hook entries, and zero-ref Release may free/reuse the object. R02t retains raw table addresses in a process-wide 32-table journal and cannot distinguish a reused address/generation. | Prove device identity/retirement, Reset reinstallation or equivalent handling, current full table and variant, and an exclusive native phase before designing a new adapter. Mere `MEM_PRIVATE` readability is insufficient. |
| Patch the authenticated static image templates A/B before original CreateDevice | **Promising conditional strategy, not implemented or phase-authorized.** The bounded constructors select A/B before the 175-word embedded copy, and Reset's 119-word recopy reads the saved static template; prepatched slots16/17 would propagate through both copies on that path without journaling freed heap addresses. Template C is transient on this traced constructor path. | Prove all active device/template routes and existing-device ordering, exact current image-table identity, safe exclusive publication/recovery and cross-device effects; retain original targets before any static slot is exposed. A prior device or foreign template modification could bypass this scheme. |
| Intercept immutable provider method entry instead of a per-device table | **Unproved alternative**, not an authorized patch. The observed method targets are in authenticated provider code, but method-entry interception may affect other objects and requires its own complete ABI, instruction/relocation, reentrancy, provider lifetime, phase and recovery contract. | Do not substitute a shared code hook for device-scoped proof based on one sampled object. |

The coherent next S02 action, if separately assigned, is to develop and test the **pre-CreateDevice authenticated static-template transaction contract** on owned x86 Direct3D9 SDK objects with the pinned real system provider: exercise flags `0x42`, CreateDevice, Reset, Release/recreate and hook-slot inheritance with exact provider authentication, bounded publication/recovery and no proprietary game code. This can decide the template approach's native behavior without journaling freed heap addresses; it still cannot certify original-game exclusive phase or every device/driver route. This packet implements or launches none of it. `HookPresent`'s transitive UI/diagnostic/frame-cap phase and the separate M3 other-thread condition remain open. Production startup remains Rejected/WITHHELD; frozen MP/FPU/POP/savings controls and all settings are unchanged, and no performance result is claimed.

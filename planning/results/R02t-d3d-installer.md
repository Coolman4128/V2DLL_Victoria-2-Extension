# R02t — D3D9 import and dependent vtable installation

The default-on D3D installer now treats the EXE `Direct3DCreate9` import and the returned `CreateDevice`, `Reset` and `Present` vtable slots as one reported family. The transaction authenticates the pinned active import, retains its loaded d3d9 provider, verifies the provider disk image and relocation-normalized mapped `.text` before its first write, and checks each returned table's immutable provider-image storage and exact relocated method-slot baseline. A new table is rejected if an earlier owned slot changed or its original method tuple differs from the process-wide published tuple. The returned COM objects are not retained or AddRef'd.

Each original callback target is published before its hook pointer can appear. One aligned pointer compare-and-exchange installs the EXE import or `CreateDevice` slot; the device stage prepares both originals before installing its adjacent `Reset` and `Present` slots. Reverse recovery verifies original pointers and restores protection. Clean rollback, Busy, foreign edits, provider mismatch and incomplete recovery have distinct reports. A known or possibly exposed hook keeps its original provider pointer and retained module reference valid after rollback; a conflicting later tuple is terminal. The first EXE-import Busy result can defer to a later no-wait retry. A returned object/device cannot be held for retry, so per-object Busy and other stage failures mark the family unavailable. Fixed journals support at most 32 CreateDevice tables and 32 device-pair tables; an additional table fails closed. Earlier independent installer effects may remain. The three stages and four slot writes are not process-wide atomic and still require a verified exclusive native phase.

The existing provider call order, `D3DCREATE_FPU_PRESERVE` flag, optional present-interval edit, `HRESULT`, output object and callback bodies remain the successful-path behavior. A clean installer failure after the provider returns does not replace a successful native result with `E_FAIL` or discard the object. The raw `PatchVtableSlot` route was removed; `TryPatchLateModules` now stops later dependent installation when the D3D family is unavailable. No D3D runtime call, game process, candidate launch, deployment or Steam file was touched. Production startup remains hard Rejected/WITHHELD.
